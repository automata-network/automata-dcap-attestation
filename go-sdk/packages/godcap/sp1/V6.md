# SP1 v6 transport

`NewV6Client` is an explicit opt-in for SDK **6.8.0**, circuit **v6.1.0**.
`NewClient` retains its legacy v5 default. Do not set the network circuit to
`v6.8.0`: SDK and circuit versions are different.

Use a reviewed ELF64 guest's native ID and the canonical compact-V2 ABI input.
`NewSP1StdinFromInput` encodes that input. `Client.Prove` submits a Groth16 auction
request and may incur network fees; tests do not submit such requests. The
legacy `zkdcap.ZkProofClient` convenience flow still uses its old embedded program
and old input format; it is not a compact V2 proof generator.

The v6 decoder follows `ProofFromNetwork` from the pinned upstream SDK:

- Groth16 enum discriminant 3, five decimal-string public inputs.
- Encoded proof, raw proof, verifier hash, public-values buffer, circuit version.
- No trailing bytes, no optional TEE field from local SDK save files.
- EVM bytes: selector `0x4388a21c` plus 352 bytes containing exit code, recursion
  root, nonce and eight Groth16 words (356 bytes total).

The transport checks the expected circuit/verifier, successful exit, recursion
root, journal commitment and requested native ID. These checks **do not verify
the Groth16 pairing**. Use a trusted Rust SDK or the configured on-chain verifier
to verify the proof before treating the output as authenticated. An application
then binds its separately supplied report body to the verified `quoteBodyHash`.

Offline tests cover format, all truncation points, wrong version/ID/root/exit,
modified journal, malformed decimal inputs and wrong lengths. The synthetic
zero-point fixture is deliberately not a valid cryptographic proof. A genuine
v6 network roundtrip and proof acceptance remain release tests.
